# Changelog

## Unreleased

## 0.1.0

- **GPUI library** — The GPUI channel's crates: `xds-ui` and `xds-tokens`, for GPUI Kit 0.9.1 exactly and Rust 1.100, `preview` while GPUI is 0.x, with the preset themes as constants in `xds_tokens::themes`. They are built and checked as the other channels' packages are: a crate outside the repository that takes them in place of crates.io's draws every page and overlay of the design preview off screen exactly as a scaffolded project does, with the default theme and a custom one. The release publishes them to crates.io after that check, and a rehearsal has crates.io accept the publishing token for both. See [the GPUI library](docs/gpui-library.md).
- **CLI** — `xds export-theme --format gpui` writes a checked theme file as a Rust `Theme` constant for the GPUI components.
- **GPUI scaffold** — The tokens are a value: `Theme` holds the colors of both modes, the sizes of both input devices and one struct per group of shared values, `DEFAULT_THEME` is the one the token files describe, and `set_theme` registers another with the app. The components read every token from the registered theme with `theme(cx)` and `palette(cx)`, and the constants give way to its fields: `SPACE_4` is `theme.space.s4`, `POINTER` is `theme.pointer`, and `colors(mode)` is `theme.colors(mode)`. `set_defaults` registers the variant, size, tone, shape, ratio or layout the components take when the app passes none. Every component implements `Styled` and puts the app's style on its root, or on its surface for an overlay. `button` and `icon_button` take their variant and size with `.variant` and `.control_size`, and no context; `text` takes `.variant(TextVariant::…)` and `.tone(TextTone::…)` in place of a `Typography`; `icon`, `icon_filled` and `spinner` take `.icon_size` and `.spinner_size`; `Banner::new` takes the message, and `.tone`; `Avatar` and `AvatarStack` take `.avatar_size`. `ControlSize::height` takes the theme and `font` the context. The UI crate re-exports the tokens crate as `tokens` and GPUI Kit as `gpui_kit`. `mise run //desktop:render` draws every page and overlay of the design preview off screen into PNG files.

- **GPUI and Tauri scaffold** — Rust 1.100. The workspace lints with Clippy's pedantic group and the lints that bring the pinned release's idioms (`map_or_default`, `is_none_or`, `#[expect]` with a reason), and the project's `AGENTS.md` lists the idioms no lint proposes.

- **React Native library** — The first React Native channel: `@xds/react-native` on npm under the `preview` dist-tag while React Native is 0.x, for React Native 0.86 to 0.88 and Expo SDK 58, with the tokens inside it and the preset themes in `@xds/react-native/themes`. Expo's glass modules are optional peers: without them the glass surfaces are opaque. The release publishes it after an Expo app and apps on React Native 0.86 and 0.88 without Expo install, type-check and bundle it, and draw the design preview as the scaffolded app does, with the default theme and a custom one. See [the React Native library](docs/react-native-library.md).
- **CLI** — `xds export-theme --format react-native` writes a checked theme file as a TypeScript `Theme` value for the React Native theme provider.
- **React Native scaffold** — `AcmeTheme` provides a theme, a color scheme or both to the components inside it, which read every token from the theme in effect: `useTheme()`, `useColors()`, and `themed()` for a style sheet built once per theme. `@acme/tokens` exports `defaultTheme` and the `Theme` type. A `Defaults` component sets the variant, size, tone, shape, ratio or layout the components inside it take by default. Every component takes a `style` for its root view, or for its surface in an overlay. Expo's blur, gradient and glass effect modules are loaded optionally. `Spinner` takes the `lg` size, drawn at the token sizes where the platform allows. `CONTROL_HEIGHT`, `control`, `AVATAR_SIZE` and `AVATAR_TEXT` give way to functions of the theme, and `datePicker.ts` and `slider.ts` are now `calendarDays.ts` and `sliderValues.ts`, so that no two modules differ only in case.
- **Compose library** — The consumer check also links the artifacts into iOS frameworks for the simulator and for devices. The contract records that Compose's `Text` takes its variant as the type role itself.

- **Compose library** — The first Compose channel: `io.github.kjmin-dev:xds-ui` on Maven Central, for Android, iOS and the desktop JVM, with the preset themes as values in `xds.themes`. It is `preview` while kotlinx-datetime is 0.x. The release publishes it after a desktop app and an Android app outside the repository draw the design preview exactly as a scaffolded project does, with the default theme and a custom one. See [the Compose library](docs/compose-library.md).
- **CLI** — `xds export-theme --format compose` writes a checked theme file as a Kotlin `Theme` value for the Compose theme composable, in the package `--package` names.
- **Compose scaffold** — The tokens are a value: `Theme` holds the colors of both modes, the sizes of both input devices and the shared values, and `AcmeTheme(mode, input, theme)` gives it to the components, which read every token from the theme in effect. An `AcmeTheme` inside another keeps the outer mode, input and theme unless it is given its own. `input: Input` replaces `sizes: Sizes`, and `PointerSizes`, `TouchSizes`, `LightColors`, `DarkColors` and `colors(mode)` give way to `DefaultTheme.pointer`, `.touch`, `.light`, `.dark` and `theme.colors(mode)`. The group objects (`Space`, `Radius`, `Typography`, …) are now composable properties of the theme in effect, so they are read in composition. A `Defaults` composable sets the variant, size, tone, shape, ratio or layout the components inside it take by default. The design preview's `DesignPreviewScreen` and `PreviewOverlay` are public, and the module exposes Compose as an `api` dependency.

- **Web library** — The first web channel: `@xds/react`, `@xds/solid`, `@xds/vue` and `@xds/svelte`, with `@xds/core` and `@xds/tokens`, published under the `preview` dist-tag while Zag.js 2 is a prerelease. Each framework package has a finished stylesheet in the `xds` cascade layer that styles only the library's own elements, a stylesheet for apps with Tailwind CSS 4.1 or later, and an optional page stylesheet. `@xds/tokens/themes/<name>.css` applies a preset with `data-xds-theme`. See [the web library](docs/web-library.md).
- **CLI** — `xds export-theme <file>` checks a theme file and writes it as a stylesheet: for the web library outside a project, or with the project's names inside one.
- **Web scaffold** — Every component takes a class (`className` in React) and a style on its root element, which carries a stable root part class such as `acme-button`. A `Defaults` component sets the variant, size, tone, shape, ratio or layout that the components inside it take by default. The part classes of the components drawn with a stylesheet now start with the project's name (`.button` is `.acme-button`, `.dialog__title` is `.acme-dialog__title`), and so does `--acme-layer-overlay`. `data-theme` sets the color mode on any element, not only on the root element.

- **CLI and all library channels** — The theme contract lists the public color, size and foundation tokens and their types. `xds check-theme` validates custom themes and reports failing contrast pairs in light and dark mode, including glass surfaces.
- **CLI** — New projects retain the version of xds that created them when adding targets with a later CLI.
